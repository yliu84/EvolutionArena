# Project Charter

## Vision

Evolution Arena is a browser action-evolution game in which the player begins as a weak creature, hunts an ecosystem, absorbs genes, automatically grows according to those hunting choices, visibly changes body and abilities, and decides when to challenge the final boss after reaching an Apex form.

The emotional promise is not merely **“level up.”** It is:

> **“I built this creature through the things I chose to hunt.”**

## North-Star Experience

A successful run should create five feelings in sequence:

1. **Vulnerability** — I am small and must choose safe prey.
2. **Curiosity** — What genes can I find this run?
3. **Transformation** — My creature visibly becomes different.
4. **Power** — My build starts producing satisfying combat advantages.
5. **Temptation** — After victory or death, I immediately imagine a different build and want another run.

## Product Pillars

### 1. Hunt shapes evolution
Randomness exists, but the player shapes it by choosing prey, region and elite targets. The primary choice is what to hunt; the game does not stop for a three-card mutation draft.

### 2. Evolution must be visible
Important mutations change silhouette, VFX, animation, attack pattern or movement — preferably several at once.

### 3. Every route changes play
Flat stat gains may support a mutation, but each family must eventually change positioning, timing, target choice or survival behavior. Trade-offs should be added where they improve route identity without making an automatic evolution feel like punishment.

### 4. Runs are restartable, with optional overgrowth
Initial validation target: **12–18 minutes** for a normal clear. There is no hard timer. At the sixth evolution the player may challenge the boss or remain in an increasingly dangerous world. Do not expand to a 25–45 minute long-run structure until observed median run time naturally exceeds about 18 minutes.

### 5. Familiar map, unpredictable ecology
The first version uses one learnable map. Replayability should come from authored safe spawn anchors, randomized zone populations, elites, rare resources and events. Runtime procedural macro-terrain generation is not required.

### 6. Browser first
The validation build must launch quickly from a URL and run well on ordinary desktop/laptop browsers.

## Non-Goals for v0.1

- Real-time multiplayer
- Accounts/login
- Seasons/battle pass
- Paid skins
- Ads/IAP
- Per-run procedural macro-terrain generation
- Dozens of bosses
- Fully free-form AI-generated anatomy
- Permanent stat advantages
- Mobile-first controls
- Competitive ranking

## Scope Rule

A proposed feature enters v0.1 only if it materially improves at least one of:

- desire to make another build;
- meaningful hunting decisions;
- evolution feedback;
- combat readability;
- run pacing;
- ability to validate player retention.

Everything else goes to the backlog.
