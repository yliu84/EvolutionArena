## 一、长度是从时间预算推出来的，不是拍的

用户目标：一张地图玩 20–30 分钟。取中值 25 分钟（1500 秒）。

| 项 | 秒 |
| --- | --- |
| 6 个窝点战斗（6 × 110） | 660 |
| 2 个区域首领（2 × 70） | 140 |
| 终局 Boss | 110 |
| 选择面板 7 次 × 15（5 变异 + 2 进化） | 105 |
| **战斗与选择合计** | **1015** |
| 剩余移动时间 | 485 |

移动路径总长 = 485 × 6.2（`PLAYER_SPEED`）× 0.70（路径效率）= **2105 世界单位**
减去支线往返（6 窝点 × 2 × 45）= 540
**→ 主路单程 ≈ 1565，取整 1600**

端到端不停步 = 1600 / 6.2 ≈ **4.3 分钟**。

对比：现有幽影林地是 50 × 36，横穿 8.1 秒。**河谷是它的 32 倍长。**

### 路线（2026-08-18 第二次修订）

> 初版是一条沿 x 的直线。**建出来以后一眼就看出问题：一条走廊走到头，没有方向可选，也没有回头看的理由。** 现在主路是世界里的一条折线，**每个拐角都是一片开阔地**——走一段、豁然开朗、换个方向再走。

主路拐点（世界坐标）：`(40,0) (330,40) (560,210) (760,120) (980,330) (1180,250) (1420,470)`，五个拐角，转角 60–70°，拐角处圆角化（半径 62）。全长 **1590**。

**所有度量改为沿路线的弧长 s，不再用 x。** 路线会折回自己旁边，世界 x 相同的两点可能相隔几百米路程——这正是必须换参数的原因。拐角必须圆角化还有一个更硬的理由：折线的法线在拐角是突变的，「最近点投影」（地形用它量）和「沿法线偏移」（河面网格用它建）在拐角处结果不一致，**河就被切成一节一节的**。

### 谷宽

| s 区间 | 半宽 | 作用 |
| --- | --- | --- |
| 五个拐角附近 | **38** | 开阔盆地，窝点与首领战场 |
| 隘口 ±34（s=440 / 950） | **9** | 收窄，物理不可绕过 |
| 其余 | 22 | 过渡走廊 |

可行走面为半宽的 **0.60**（`walkShare`，单一常量）。崖面从可行走边界起算，17 高——**高于镜头**。

### 路与河

路偏在半宽的 0.22 处。**河道宽度不是拍一个比例，是按路边实际剩下的地面算出来的**：隘口只有 9 的半宽，放不下一条全宽的路加一条全宽的河，此时河让路。这样路与河、河与崖脚都不可能重叠——不是调参数调到测试通过，是构造上不可能。

河道**比水面宽 1.62 倍且是平底的**。初版河道是个窄 V 形，水面却按全宽画成平面，两岸就从水面里冒出来把河切成段。

**两处浅滩**（s=400 / 1420）：河床抬到水面附近，可以蹚过去。**除了浅滩，任何地方都过不了河**——落水会被推回你进来的那一岸，不是推到最近的干地（那等于送一次免费瞬移过河）。

## 三、随机化规则

**位置与原型都随机。**

- 每区 3 个候选位，实际只激活 **2** 个 → 每区 3 种位置组合
- 原型从该层抽取：一层 3 个、二层 3 个、三层 **只有 2 个**

三层只有两个原型（黑茧高巢、沉没母巢），所以**必须靠位置随机来保证第三区仍有路线变化**——否则每局第三区都一样。这是位置随机存在的原因，不是锦上添花。

## 四、与已实现系统的对接

| 系统 | 对接方式 |
| --- | --- |
| 变异闸门 | 5 个里程碑 = 进入区域 ×3 + 区域首领 ×2。运行时记录的是不透明 id，只需换数据源。 |
| 存活次数 | 起始 3；经过 R1 / R2 各补 1，上限 4。 |
| 检查点 | 命归零时从当前区域起点重来，**保留已获得的变异与形态**。25 分钟的局不能因一次失误全废。 |
| 形态进化 | 区域一末尾（0→1 阶）、区域二末尾（1→2 阶），由生物质解锁。 |
| 回血 | 沿用窝点的 `heal` 奖励（24–38），**不撒落地拾取**。 |

## 五、需要环境工作流提供的

本规格不含任何美术改动，只需要三项结构：

1. 沿 x 0–1600 的可行走边界（按第二节的半宽表）
2. 9 个窝点候选位的地面（各需容纳 `combatRadius`）
3. 两处隘口与终局场地的地形

主题为河谷：谷底主路、两侧岩壁、三处开阔盆地。**不要求改现有幽影林地的任何资源。**

## 六、生物：小怪沿用，三个首领全部新做（用户 2026-08-18 决定）

### 一个必须先说清楚的事实：这个项目从来没有过建模的首领

- **荆心守卫**（现有 Boss）不是模型，是 Three.js 基本几何体拼的——十二面体、二十面体、锥体、圆柱，约 30 个 mesh。
- **腐根巢卫**（现有巢卫）没有自己的视觉，它是把岩盾小怪的模型放大 `bodyScale: 1.28`。

所以「首领全部新做」意味着**做这个项目的第一批首领模型**。这不是重复已验证的流程，是第一次做这类资产。

好消息是**片段数量与玩家形态相当**：玩家形态 9 段（Idle/Walk/Run/Turn + 3 攻击 + Hit/Death）；一个三招式首领也是 9 段（Idle/Walk/Turn + 3 招式 + Hit/Death）。已验证的 Meshy → 修复脚本 → 运行时管线可以直接复用。

### 小怪：沿用

三个已生产家族（裂牙 / 岩盾 / 群生）跨地图复用，不做新物种。河谷最多做地域配色变体，不做新模型。**一张新地图的生物成本因此只有 3 个首领，而不是一整套生态。**

### 招式形状必须复用现有三种，否则会引入新权威

现有 Boss 的判定只有三种几何：

| 形状 | 参数 | 现有用例 |
| --- | --- | --- |
| 圆 | `radius` | root-slam 3.35 |
| 线段 | `length` + `halfWidth` | thorn-charge 6.4 × 0.82 |
| 环 | `innerRadius` + `outerRadius` | spore-ring 2.15–5.15 |

**三个新首领的招式全部用这三种形状，只换数值。** 引入第四种形状（锥形、移动灾害、多段弹幕）等于新的判定权威——和远程 / 魔法一样，那是独立的一项风险，不应该和「第一批首领模型」同时做。

### 排产建议

一次只引入一个新东西：

1. **先做隘口一那一个**，把「首领建模 + 招式动画」这条路走通并拿到成本数字
2. 再做隘口二
3. 终局 Boss 最后——它是两阶段，片段最多

三个都不要和 venom / wing / rift（新攻击权威）同期做。
