### G-1 详情

引导第 5 步文案为「腐根巢卫正面防御很强；绕到侧后攻击，击破后通往Boss」（`src/gloamwood-3d-onboarding.ts:87`）。机制侧确实存在方向倍率（`src/gloamwood-3d-ecology.ts:227-229`）：正面 ±75.6° 扇区内伤害 ×0.28，扇区外 ×1.35。

但几何上无法达成：

- 巢卫属岩盾家族，转向 `turnSpeed = 3.1` rad/s（`gloamwood-3d-ecology.ts:92`），且转向在各状态下持续生效
- 玩家速度 `PLAYER_SPEED = 6.2`（`gloamwood-3d-hunt.ts:121`）；巢卫 `bodyRadius = 1.82`，近战绕行半径约 2.6，对应绕行角速度约 `6.2 / 2.6 ≈ 2.4` rad/s
- 3.1 > 2.4，巢卫始终快于玩家绕行；即使从背后起手，相对角也会以约 0.7 rad/s 收敛回正面扇区
- 要超过 3.1 rad/s 需把绕行半径压到 2.0 以内，而巢卫体半径本身即 1.82，碰撞不允许

附带确认：**Boss（荆心守卫）没有任何朝向倍率**，`damageGloamwoodBoss()`（`src/gloamwood-3d-boss.ts:58`）为平伤，绕后无机制收益；其转向 4.2 rad/s 亦远高于玩家在 `preferredRange 3.82` 处的绕行角速度约 1.63 rad/s。Boss 引导文案本身没有要求绕后（`bossSafetyHint` 只说读预警与安全区），因此 G-1 的文案与机制矛盾仅存在于巢卫。

候选处理方向（未实施，待用户选择）：降低巢卫转向速度使绕后可达；或在其出招/前摇期间锁定朝向留出绕后窗口；或改写引导文案，把要求从「绕后」改为机制上真实可行的行为。**不得为此改动权威伤害、射程或碰撞去「凑手感」。**

### G-1 处理结论（2026-08-17）

用户选择方案 2：出招期锁定朝向。`GloamwoodPreySpec` 新增类型化字段 `commitsFacingWhileAttacking`，岩盾家族为 `true`、裂牙与群生为 `false`。`stepPrey` 仅在 `chase` 相位（或未承诺的家族）重新获取朝向，因此岩盾与巢卫在 `telegraph → strike → recover` 期间保持起手瞬间选定的朝向，回到 `chase` 才重新对准玩家。

- 承诺窗口 = 1.05 + 0.48 + 1.08 = **2.61 秒**；玩家绕出 75.6° 正面扇区约需 0.55 秒，仅 telegraph 一段即足够
- 转向速度、伤害、射程、碰撞、攻击命中判定**均未改动**；猎物攻击本就只判距离不判朝向，因此本次修改不改变玩家承受的伤害
- 裂牙与群生没有正面倍率机制，行为保持不变，Goal 2/3/4 已验收平衡不受影响
- 调试状态新增只读的 `prey[].facing` 与 `prey[].playerBearing`，便于在真机上直接确认承诺窗口
